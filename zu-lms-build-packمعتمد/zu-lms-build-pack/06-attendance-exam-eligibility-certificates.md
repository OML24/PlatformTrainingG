# 06 — المحاضرات والحضور والامتحان والاستحقاق والشهادات

## 1. المحاضرات (`ILectureService`) — `lecture.manage`
- **إضافة محاضرة:** الدورة `Approved` فقط (بعد `Finished` ممنوع: `COURSE_FINISHED`). الحقول: العنوان (اختياري)، **النمط** (`InPerson`/`Online`؛ لدورة وجاهية يُفرض `InPerson`، لأونلاين `Online`، للمدمجة يختار المحاضر لكل جلسة)، التاريخ، وقت البداية، وقت النهاية (منتقيات Bootstrap، وتُحوَّل من توقيت عمّان إلى UTC في الخادم)، **المكان** (وجاهي)، **رابط Teams** (أونلاين، إلزامي ويبدأ `https://`)، ملاحظات. يُولَّد `attendance_code` عشوائي (`RandomNumberGenerator`) بطول `attendance.code_length` حقولاً رقمية.
- بعد الإضافة: تظهر فوراً في جدول المتدربين مع **إشعار** «أنشأ المحاضر محاضرة جديدة» لكل المشاركين الفعّالين. المحاضرات الإضافية/الورش/التعويضية كلها محاضرات عادية.
- **تعديل** المحاضرة (التوقيت، المكان، الرابط) قبل `Finished`. **تعطيل** (`is_active=false`) يملكه المحاضر فقط إن لم تُسجَّل لها أي علامة حضور وقبل الإنهاء [م7]، وإلا الأدمن. المحاضرة المعطّلة لا تُحتسب في `N`.
- **المواد:** رفع ملفات (`files.ext.materials`) وربطها بمحاضرة (`course_files.lecture_id`)؛ يحمّلها المشاركون الفعّالون.
- **إنهاء الدورة** (`course.finish`) في §7.

## 2. كود الحضور (`IAttendanceService`)
**التفعيل** (`attendance.activate_code`): `POST /lectures/{id}/activate-code` → `code_activated_at=الآن`, `code_expires_at=الآن + attendance.code_validity_minutes`. **مسموح فقط** إذا لم يكن هناك تفعيل ساري (`code_expires_at <= الآن` أو NULL)؛ يعيد تفعيل **الكود نفسه** لفترة جديدة. الدورة `Approved`. لا تغيير على الكود. تُعرض للمحاضر شاشة كبيرة بالكود وعدّاد تنازلي (وفي الأونلاين تُعرض على الشاشة المشتركة).
**إدخال المتدرب** (`attendance.enter_code`): `POST /lectures/{id}/enter-code {code}` بالخوارزمية:
1. المستخدم مشارك **فعّال** في دورة هذه المحاضرة والمحاضرة فعّالة والدورة `Approved` وإلا `ATT_NOT_PARTICIPANT`.
2. إن كان محظوراً (`attendance_code_attempts.locked_until > الآن`) → `ATT_LOCKED`.
3. الكود غير مفعّل أو منتهٍ → `ATT_CODE_EXPIRED`. (لا يُحسب خطأ كود.)
4. الكود ≠ كود المحاضرة → `wrong_count++`؛ إن بلغ `attendance.max_wrong_attempts` → `locked_until = الآن + attendance.lock_minutes` وتصفير العداد؛ `ATT_CODE_WRONG`.
5. مطابق → upsert `attendance_records(is_present=true, source=Code, marked_at=الآن)` + صف `attendance_changes` + تصفير العداد → `IEligibilityService.RecalculateParticipant`. يظهر التحديد فوراً في كشف المحاضر (يستطلعه كل 5 ثوانٍ أو عند الفتح).
المقارنة بزمن ثابت. الإدخال لمحاضرة **أخرى** يُرفض لأنه مرتبط بمعرّف المحاضرة في المسار.
**التحديد اليدوي** (`attendance.edit_manual`): في كشف المحاضرة مربع بجانب كل مشارك: تحديد/إزالة أي مشارك **سواء أدخل الكود أم لا**، أثناء الدورة وبعد `Finished` وبعد صدور الشهادة (`attendance.allow_edit_after_finish`). آخر تعديل محفوظ هو المعتمد. كل تعديل يضيف `attendance_changes` (من، سبب اختياري) ثم **إعادة تقييم الاستحقاق** (§5). إن فُقد الاستحقاق تُلغى الشهادة (`AttendanceCorrection`).
**واجهة المتدرب:** في تفاصيل الدورة قائمة محاضرات بطاقة لكل محاضرة (العنوان، الموعد، النمط، المكان/رابط Teams، حالة حضوري) + **خانة إدخال كود مستقلة** لكل محاضرة بعدد خانات الكود. عداد لحظي: «حضرت X من N — الحد الأدنى للاجتياز M (نسبة T%)». أثناء الدورة المؤشر **مبدئي** ولا يصدر حكم رسوب قبل الإنهاء.

## 3. نسبة الحضور (المصدر الوحيد `AttendanceRules`)
`N` = عدد المحاضرات الفعّالة (`is_active`) للدورة؛ بعد الإنهاء `N = final_lectures_count` (مثبّت).
`T` = `attendance_threshold_percent_override` للدورة إن وُجد وإلا `attendance.threshold_percent`.
`حضر` = عدد `attendance_records.is_present=true` على محاضرات فعّالة.
`M = ceil(N × T / 100)` بحساب صحيح: `(N*T + 99) / 100`. مستوفٍ = `N>0 && حضر >= M`.
أمثلة إلزامية (اختبارات): N=10,T=75 → M=8 (7 رسوب، 8 نجاح). N=4 → 3. N=8 → 6. N=5 → 4.
**لا حكم نهائي قبل `Finished`.** بعد الإنهاء: `< M` ⇒ «لم يستوفِ شرط الحضور (حرمان)».

## 4. الامتحان الخارجي (`IExamService`)
- `has_exam` يحدده العميد في المقترح أو الجودة/الأدمن عند الإنشاء (`05`). الامتحان **يُجرى خارج المنصة**؛ المنصة لا تدير أسئلته ولا موعده ولا درجاته.
- **«إنشاء امتحان»** (`exam.manage`): في دورة `has_exam=true`، زر واحد يُدخل **اسم الامتحان** (`name_ar` إلزامي) فينشأ `course_exams` (واحد لكل دورة). إن وُجد سجل (حتى لو غير فعّال) **أعد استخدامه** (`is_active=true`) ولا تنشئ آخر.
- **شاشة سجل الامتحان:** كل المشاركين الفعّالين، لكل واحد: «لم تُرصد النتيجة» أو «ناجح» (علامة) أو «راسب». يختار المحاضر **صراحةً** ناجح/راسب ويحفظ. **ترك العلامة فارغة لا يعني رسوباً.** تغيير نتيجة يضيف `exam_result_history`.
- **قواعد النتيجة:** لا درجة رقمية. تظهر للمتدرب وللمحاضر والجودة وتدخل في الاستحقاق.
- **تغيير النتيجة إلى «راسب» بعد صدور الشهادة** → تُلغى الشهادة (`ExamResultChanged`) ويصل المتدرب إشعاراً يوضح السبب، ويُعرض في صفحته أنه مسجل ولم يستوفِ متطلبات الشهادة دون بطاقة شهادة ملغاة.
**تعديل شرط الامتحان (`exam.requirement.edit`):**
- من «بلا امتحان» إلى «بامتحان»: مسموح للأدمن والجودة؛ يعاد تقييم الاستحقاق (من لا نتيجة ناجحة له يفقد الاستبيان والشهادة: شهادات صادرة تُلغى `ExamRequirementChanged`).
- من «بامتحان» إلى «بلا امتحان»: **ضمن معاملة** في الخادم: إن وُجدت نتيجة **نشطة** واحدة أو أكثر فالجودة **ممنوعة** (`EXAM_RESULTS_EXIST`) وتُحال للأدمن؛ **الأدمن** (`exam.results.disable`) يُعطّل النتائج منطقياً (`exam_results.is_active=false` مع سبب والمنفّذ) ثم يغيّر `has_exam=false`. بعدها إعادة تقييم فورية؛ تصدر آلياً شهادات من استوفى الحضور والاستبيان بعد الإنهاء.
- إن عاد الشرط لاحقاً: **لا تُستعاد النتائج المعطّلة**؛ يلزم رصد نتائج جديدة ويعاد تقييم الاستحقاق والشهادات بالشروط الجديدة.

## 5. محرك الاستحقاق (`EligibilityRules` + `IEligibilityService`)
### 5.1 الدالة النقية
```
EligibilityInput {
  CourseStatus status; bool hasExam; int totalLectures(N); int attended; int thresholdPercent;
  ExamState exam (None | NotRecorded | Passed | Failed);
  bool surveyCompleted;      // أجاب على النسخة المطبّقة للدورة (07)
  bool participantActive; bool courseActive;
}
EligibilityResult { bool Eligible; bool AttendanceOk; bool ExamOk; bool SurveyOpen; bool ImpactOpen;
                    IReadOnlyList<string> UnmetReasons; }
AttendanceOk = AttendanceRules.IsSatisfied(attended, N, T)
ExamOk       = !hasExam || exam == Passed
SurveyOpen   = status==Finished && AttendanceOk && ExamOk      // [م9]
ImpactOpen   = SurveyOpen
Eligible     = status==Finished && courseActive && participantActive && AttendanceOk && ExamOk && surveyCompleted
```

قياس الأثر **اختياري بالكامل** ولا يدخل في `Eligible` ولا يمنع إصدار الشهادة، سواء لم يرفع المتدرب طلباً أو كان الطلب `Submitted` أو `Returned`. يبقى الرفع والمراجعة والاعتماد والتقارير كما هي لأغراض قياس الأثر فقط.

**استحقاق الدورة التاريخية:** قيمة `historical_passed` التي يحددها الجودة أو الأدمن هي القرار الحاكم. `true` تجعل الحضور والامتحان مستوفيين ضمنياً، و`false` تمنع الشهادة. إذا كان `evaluation_exempt=true` تصدر الشهادة فور حفظ الدورة؛ وإذا اختير أن التقييم مطلوب، يكون `EVALUATION_MISSING` السبب الوحيد المتبقي وتصدر الشهادة مباشرة بعد إرسال التقييم. لا يمكن إنشاء امتحان أو محاضرة أو تغيير شرط الامتحان لدورة تاريخية.
(الدورة `Cancelled` أو غير فعّالة ⇒ `Eligible=false`.)
### 5.2 الخدمة `RecalculateParticipant(courseId, participantId)` و`RecalculateCourse(courseId)`
تُستدعى **ضمن المعاملة نفسها** عند: إنهاء الدورة، أي تعديل حضور، نتيجة امتحان، تغيير `has_exam`، تعطيل نتائج، إرسال استبيان، إضافة/إخراج مشارك، تغيير نسبة الحضور (الإعداد أو التجاوز)، إعادة فتح دورة، استعادة دورة، رفع قالب الشهادة (`issue_pending`). مراجعة الأثر قد تحدث العرض لكنها لا تغير استحقاق الشهادة.
المنطق:
1. احسب المدخلات من القاعدة ثم `Evaluate`.
2. **مستحق ولا شهادة `Issued`:** أصدر شهادة (§6). إن لم يوجد قالب حالي → لا تفشل: سجّل `CERT_TEMPLATE_MISSING` وأبقِ الاستحقاق (تُصدر لاحقاً بـ `certificates.issue_pending` أو آلياً عند رفع القالب).
3. **غير مستحق وله شهادة `Issued`:** ألغِها (`Revoked`) بالسبب المناسب: حضور→`AttendanceCorrection`، امتحان→`ExamResultChanged`/`ExamRequirementChanged`، إخراج→`ParticipantRemoved`، إعادة فتح→`CourseReopened`، إلغاء دورة→`CourseCancelled`. **استثناء:** إن كان سبب فقدان `surveyCompleted` هو نشر نسخة تقييم جديدة **فلا تُلغَ** الشهادة (تبقى سارية ويطلب منه إعادة التقييم) — احسب `surveyCompleted` للشهادة القائمة بأنه صحيح.
4. أرسل إشعاراً للمتدرب عند الإصدار/الإلغاء، وسجّل في audit.

## 6. الشهادات (`ICertificateService`)
### 6.1 الإصدار (ذرّي)
1. الرقم المرجعي: `CertificateReference.Format(cert.reference_pattern, سنة الإصدار بتوقيت عمّان, CODE, seq, cert.reference_padding)` حيث `CODE` = `short_code` للكلية صاحبة الدورة (`proposing_center_id` للمقترحات، وإلا `target_center_id` إن `Faculty`) وإلا `cert.general_short_code`؛ إن كان `short_code` فارغاً استخدم العام. `seq` من `number_sequences('CERT:{yyyy}:{CODE}')`.
2. `verification_token` = 32 بايت عشوائي base64url.
3. لقطة البيانات المجمّدة: اسم الحاصل (`full_name_ar/en`)، عنوان الدورة، **فترة الدورة** (من أول محاضرة فعّالة إلى آخرها: `dd/MM/yyyy – dd/MM/yyyy`)، الساعات، **اسم المحاضر الفعلي** (`instructor_name_*` وليس حساب الجودة)، تاريخ الإصدار.
4. ولّد PDF (§6.2) وخزّنه كملف (`CertificatePdf`) وسجّل `pdf_file_id`، و`template_id` المستخدم.
5. `status=Issued`, `issued_at=الآن`. أضف في المستودع المركزي؟ **لا** (الشهادات ليست كتباً رسمية). إشعار للعضو.
### 6.2 توليد الـ PDF (`ICertificatePdfRenderer`)
- القالب: PDF ثابت يرفعه الأدمن. **ليس حقولاً قابلة للتعبئة.**
- طبقة النصوص: QuestPDF بصفحة بحجم القالب (`page_width_pt × page_height_pt`) **شفافة**، تُرسَم فيها النصوص و QR في **إحداثيات مطلقة** من `layout_json`، ثم **تُدمج فوق القالب** (`DocumentOperation.LoadFile(template).OverlayFile(textLayer)`).
- الخط: Tajawal (مضمَّن، مسجَّل في QuestPDF) لدعم الربط العربي واتجاه RTL؛ للنص الإنجليزي أو الأرقام اللاتينية Tajawal كذلك.
- `layout_json` (يقدّمه صاحب المتطلبات ويضبطه الفريق برمجياً، لا محرر بصري):
```json
{ "unit":"pt", "origin":"top-left",
  "fields": {
    "holder_name":  {"x":0,"y":0,"w":0,"h":0,"font":"Tajawal","size":28,"weight":"bold","color":"#022C5A","align":"center","dir":"rtl","maxLines":1,"shrinkToFit":true},
    "course_title": {...}, "course_period": {...}, "course_hours": {...},
    "instructor_name": {...}, "issue_date": {...}, "reference_no": {...},
    "qr": {"x":0,"y":0,"size":90}
  } }
```
كل الحقول المذكورة إلزامية؛ إحداثيات `0` مؤقتة حتى يصل ملف المواضع (انظر §9). النص الأطول من `w`: صغّر الخط حتى `minSize` (60% من `size`) ثم قصّ على سطرين (`maxLines`).
- محتوى QR: `{cert.verify_base_url}?cert={reference_no}` عبر `IQrCodeService` (PNG 600px، تصحيح أخطاء M).
- اختبار إلزامي: توليد شهادة باسم عربي طويل ووجود أحرف متصلة وأرقام، والتأكد من عدم انقلاب الاتجاه (لقطة PDF→صورة).
### 6.3 صفحة التحقق العامة `/verify?cert={reference_no}` (بلا دخول، محدودة المعدل)
| الحالة | العرض |
|---|---|
| `Issued` و`is_active` | «شهادة سارية»: اسم الحاصل، عنوان الدورة، فترتها، ساعاتها، المحاضر، تاريخ الإصدار، الرقم المرجعي. **بلا** حضور ولا نتيجة امتحان ولا بيانات اتصال |
| `Revoked` | «**شهادة ملغاة**» + تاريخ الإلغاء (دون السبب التفصيلي) |
| `is_active=false` (عُطّلت مع دورتها) أو غير موجودة | «لم يُعثر على شهادة بهذا الرقم» (لا تفاصيل إطلاقاً) |
### 6.4 العرض في الملف الشخصي والتنزيل
- `/shared/profile/{userId}`: بطاقات **الشهادات السارية فقط** (`Issued` و`is_active`) بتصميم البروتوتايب: عنوان الدورة، تاريخ الإصدار، الرقم المرجعي، رمز QR، زر «تحقق» (يفتح صفحة التحقق). **لا تظهر** شهادة ملغاة أبداً. لا تظهر نتائج الامتحان/الحضور.
- **تنزيل PDF لصاحبها فقط** (`certificates.download.own` + `user_id = المستخدم`؛ غير ذلك `403`).
- قائمة المتدرب لدورة لم يستوفِ متطلباتها: «مسجّل في الدورة — لم يستوفِ متطلبات الشهادة» (لكل مشارك غير مستحق بعد الإنهاء، بما فيهم من لم تصدر له شهادة قط).
### 6.5 قالب الشهادة (`/admin/certificate-template`، `cert_template.upload`)
- زر **رفع قالب** متاح في أي وقت: PDF صفحة واحدة، حد الحجم `files.max_mb.cert_template`، يُفحص أنه PDF حقيقي وصفحة واحدة، تُقرأ أبعاده. + رفع `layout_json` (ملف JSON يُتحقق من مخططه) مع القالب. تُنشأ نسخة جديدة `version_no+1` وتصبح `is_current` وتبقى القديمة. الشهادات الصادرة تحتفظ بمرجعية قالبها.
- زر **«معاينة»**: يولّد شهادة ببيانات وهمية صريحة («اسم تجريبي») ويعرضها.
- بعد رفع قالب لأول مرة: نفّذ آلياً `IssuePending` لكل المستحقين الذين لا شهادة لهم.

## 7. إنهاء الدورة (`course.finish`)
زر صريح **«إنهاء الدورة»** للمحاضر (أو للجودة في المُدارة، أو الأدمن). شروط: الدورة `Approved`، عدد المحاضرات الفعّالة ≥ `attendance.min_lectures_to_finish` وإلا `FINISH_NO_LECTURES` برسالة «لا يمكن إنهاء دورة بلا محاضرة واحدة على الأقل». نافذة تأكيد تعرض عدد المحاضرات وتحذر أنه لا يمكن إضافة محاضرات بعد ذلك. التنفيذ (معاملة): `status=Finished`, `finished_at/by`, `final_lectures_count=N`، ثم `RecalculateCourse`. **بعد الإنهاء:** لا إضافة محاضرات؛ تصحيح الحضور السابق ما زال مسموحاً (ويعيد التقييم).

## 8. تقويم الاستحقاق في الواجهات
- المحاضر (`/instructor/courses/{id}/participants`): جدول: المشارك، حضر/من، النسبة، الامتحان (أو «—»)، الاستبيان (✓/✗)، الأثر (حالة)، الاستحقاق (✓/✗ + أسباب عدم الاستيفاء بالعربية)، الشهادة (رقم/ملغاة/لا).
- المتدرب: بطاقة تقدّم بالمتطلبات الأربعة وحالة كل منها.

## 9. بيانات تنتظر من صاحب المتطلبات
ملف **قالب الشهادة PDF** و**مواضع العناصر**. الطريقة الدقيقة المعتمدة لتجنب التخمين: يسلّم نسختين: (1) القالب النظيف، (2) نسخة بها نصوص دالّة في أماكنها `[[HOLDER_NAME]] [[COURSE_TITLE]] [[COURSE_PERIOD]] [[COURSE_HOURS]] [[INSTRUCTOR_NAME]] [[ISSUE_DATE]] [[REFERENCE_NO]] [[QR]]`. يستخرج الفريق الإحداثيات من النسخة الثانية بأداة (`pdfplumber`) ويكتب `layout_json`. حتى وصولها: اترك قيم الإحداثيات `0` وأضف اختباراً **متجاوَزاً (Skip)** للتوليد الكامل، وسجّل ذلك في `QUESTIONS.md`.
