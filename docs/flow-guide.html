01 / ARCHITECTURE

قبل أي كبسة: الأساس المشترك

هذه الطبقات تتكرر في معظم عمليات الموقع، لذلك اقرأها أولًا.

01 · Browser

Razor Page تبني HTML وبيانات الصفحة، ثم سكربت الصفحة يربط الأحداث. _Layout.cshtml يحمّل api.js وshell.js والإشعارات والترجمة.

02 · api.js

ZuLms.api.request(method,url,body) يرسل JSON أو FormData مع الكوكي وCSRF. يعيد محاولة CSRF مرة، ويجدّد الجلسة مرة عند 401. يفك {ok,data} إلى data ويحوّل الخطأ إلى ApiError.

03 · Routing & security

Program.cs يضبط aliases وAuthorizePage، ثم middleware للجلسة وتجديدها وتغيير كلمة المرور، فالمصادقة والتفويض. MapControllers يطابق Route + HttpVerb؛ RequirePermission يفحص الإذن مجددًا.

04 · Application → Persistence

Controller يستخرج actor/input وينادي Service في Application. الـ Service يطبق القواعد ثم يستخدم Infrastructure/EF Core للحفظ والقراءة. النتيجة ترجع HTTP؛ JavaScript يعرض نجاحًا أو خطأً ويعيد تحميل الجزء المناسب.

تسلسل الطلب النموذجيbutton / form → event listener → ZuLms.api → HTTP route → Controller.Method → ApplicationService.MethodAsync → DbContext → response → render/toast/navigation

بعض الصفحات تولّد الأزرار ديناميكيًا؛ لذلك الرابط بين اسم الكبسة والـ API ظاهر في بطاقة الاستدعاء مع سطر JS نفسه.

الجلسة والأمان

المصادقة تعتمد كوكي JWT وCSRF للطلبات المعدّلة. TabSessionMiddleware يعزل سياق التبويب، وSilentRefreshMiddleware يجدد الجلسة. صفحات HTML الممنوعة تتحول لصفحة منع الوصول؛ API يحتفظ بكود الخطأ.
