# خطوات التشغيل بعد إصلاحات QA

## أسرار التطوير

أُزيلت الأسرار المكشوفة من `launchSettings.json`. يقرأ التطبيق في Development القيم من .NET User Secrets. أضف `ZU_DB_CONNECTION` و`ZU_JWT_KEY` و`ZU_ENC_KEYS` وأي كلمة مرور bootstrap لازمة باستخدام `dotnet user-secrets set KEY VALUE --project src/ZuLms.Web`. يجب أن يكون JWT مفتاحاً عشوائياً جديداً بطول 64 بايت على الأقل، وAES مفتاحاً عشوائياً جديداً بطول 32 بايت. لا تنسخ القيم القديمة المكشوفة إلى الإنتاج.

حالة بيئة التطوير الحالية: أُعيد مفتاحا JWT والتشفير إلى القيم السابقة بطلب المستخدم، مع إبقائهما في User Secrets خارج المشروع. تدويرهما مؤجل إلى خطوة النشر.

في قاعدة موجودة، احتفظ بمفتاح التشفير القديم داخل `ZU_ENC_KEYS` مؤقتاً مع تعيين مفتاح عشوائي جديد كـ `current`، ثم شغّل `--reencrypt-secrets` بعد نسخة احتياطية. أزل المفتاح القديم بعد التأكد من قراءة البيانات. دوّر كلمة مرور PostgreSQL المكشوفة وحدّث الاتصال، وألغِ جلسات JWT القديمة بتدوير مفتاح JWT. لا تشغّل migration تنظيف كلمات المرور قبل أخذ نسخة احتياطية.

## النشر

اضبط `ZU_KNOWN_PROXIES` على عنوان Docker gateway الفعلي كما يراه التطبيق، و`AllowedHosts` على اسم النطاق الفعلي إذا اختلف عن `portal.zu.edu.jo`. التطبيق يرفض Production دون proxy موثوق. اضبط protection rules لبيئة GitHub المسماة `production`، بما فيها موافقة المراجع المطلوبة؛ مجرد تسمية البيئة في workflow لا تنشئ القواعد تلقائياً.

قبل تشغيل التطبيق في Production، شغّل `dotnet ZuLms.Web.dll --migrate` كخطوة مستقلة. Workflow النشر يفعل ذلك قبل تحديث الحاوية. بعد النشر شغّل `dotnet ZuLms.Web.dll --check-files` داخل الحاوية لمراجعة الملفات التي لها سجل بلا محتوى. استعد المحتوى المفقود من النسخ الاحتياطية بعد مطابقة المعرّف والمسار؛ الفحص لا يخترع محتوى مفقوداً.

صورة Docker المحلية `zu-lms:qa-local` بُنيت واختُبرت مع PostgreSQL 17 في وضع Production؛ نجحت خطوة `--migrate` ووصلت الحاوية إلى `healthy` وأعاد `/health` حالة سليمة. ملف Compose ينتظر فحص جاهزية قاعدة البيانات ويحفظ مفاتيح حماية الجلسات في volume مستقل. ملف `deploy/.env` الفعلي يُنشأ وقت النشر من `deploy/.env.sample` بقيم إنتاجية؛ لا تُستخدم مفاتيح التطوير القديمة ولا قيم المثال في الإنتاج.

## وظائف تحتاج استكمالاً

- عدّادات تسجيل الدخول وإعادة التحقق أصبحت في PostgreSQL، وتحتاج تطبيق migration `DistributedSecurityCounters` قبل تشغيل النسخ الجديدة. نجح اختبار تكامل PostgreSQL 17 المعتمد على Testcontainers، وفحص تشغيل صورة Docker مع ترحيل قاعدة جديدة؛ يلزم تطبيق الترحيل على قاعدة الإنتاج وقت النشر.
- مهمة تنظيف الملفات اليتيمة تعمل بعد 10 دقائق من التشغيل ثم يومياً، وتُبقي سجل الملف معطلاً وتحذف المحتوى بعد 7 أيام. راقب سجلات أول تشغيل وتأكد أن مدة الاحتفاظ مناسبة لسياسة الجامعة.
- راجع بيانات الاختبار والمحاضرين الخارجيين القديمة قبل حذفها أو تعديلها.
- أزل CSS inline بعد نقل الأنماط إلى ملفات ثابتة، ثم شدّد CSP.
